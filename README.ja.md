# Live Subtitle

[English](README.md) | 日本語 · [MIT License](LICENSE)

Mac で鳴っているすべての音声（YouTube・X・会議など、アプリを問わず）を聞き取り、選んだ言語（既定は日本語）の字幕にする macOS 用 GUI ツール（Rust / eframe・egui）。

```
システム音声 ─ ScreenCaptureKit ─ 自動音量補正 ─ 発話の区切り検出 ─ whisper.cpp (Metal) ─ 翻訳 ─ 字幕
                 16 kHz mono       (AGC)          Silero VAD        言語自動判定      内蔵 / Ollama / Claude / Codex
```

- 原文はすぐ表示し、訳は完成し次第あとから差し込む（翻訳が遅くても字幕は止まらない）。
- 翻訳は文ごとに行う。発話は短い間や 10 秒の上限で文の途中でも切れるので、文の途中で切れた残りは原文だけ先に出して待ち、次の発話とつないで文が終わってから訳す（話が 2 秒止まるか 15 秒待ったら、そのまま訳す）。断片ごとに訳すと「そして、そこには…」のような、途中で切れた訳になるため。
- 翻訳先には、話し言葉の書き起こしであることを伝え、つなぎの言葉（like、you know など）や言い直しを省き、訳す言語の自然な語順で、文末を「…」で終えないように頼んでいる。
- 訳す言語は、上の段で選ぶ（既定は「→ 日本語」）。日本語・英語・中国語（簡体字）・韓国語・タイ語・ベトナム語・インドネシア語・スペイン語・フランス語・ドイツ語・イタリア語・ポルトガル語・ロシア語から選べる。話されている言語は 1 行ごとに判定するので、whisper が聞き取れる言語なら、日本語も含めて何語の音声でも訳せる（たとえば、日本語の動画にタイ語の字幕を付ける）。選んだ言語で話された音声は、訳さずにそのまま出す。アラビア語・ヘブライ語・インドの文字の言語は選べない。egui がこれらの文字を組めず、文字がつながらなかったり順番が崩れたりするため。
- 中国語・韓国語・タイ語の文字は、macOS のフォント（Hiragino Sans GB・Apple SD Gothic Neo・Thonburi）で描く。画面のフォントに無い文字だけを、これらで補う。egui は、タイ語の記号の位置を本格的な組版ほど正確には合わせないので、母音の上に付く声調記号が少しずれることがある。
- 画面は 3 段に分かれる。上の段に「開始／停止」「帯にする」「設定」と、訳す言語・翻訳先（エンジンとモデル）、真ん中に字幕、下の段に「原文も表示」「履歴を保存」「コピー」「クリア」。めったに変えないもの（モデル一覧の更新、メモリ解放、最前面に固定、履歴の保存先、テーマ・言語・フォント・文字サイズ）は「設定」にまとめてあり、開いている間は字幕の場所に出る。「原文も表示」は、下の段と「設定」の「字幕」の両方にある。
- 画面の言語は「設定」→「表示」→「言語」で、日本語と英語を切り替えられる。「システム」のときは macOS の言語に従う（日本語でなければ英語）。翻訳先や音声の取り込みから返るエラーの文面は、日本語のまま。字幕を何語に訳すかは、これとは別に、上の段で選ぶ。
- 動作中は、上の段の下に入力音声の大きさを細いバーで出す（緑、大きいと黄色、無音は灰色で、上に「無音」と出る）。表示は自動音量補正のあとの音量で、バーに乗せると補正量（dB）が出る。
- 「履歴を保存」を押したときだけ、いまの字幕（原文・訳・時刻）を日時つきのテキストファイルに保存して、Finder で表示する（既定では何も保存しない）。保存先は既定でデスクトップ（ファイル名は `Live Subtitle 日付 時刻.txt`）。「設定」の「保存先を選ぶ…」で任意のフォルダに変えられ、選んだ場所は次回も覚えている（「デスクトップに戻す」で既定に戻る）。初回は、そのフォルダへのアクセス許可を求められることがある。
- モデル読み込み中（whisper・内蔵エンジン・Ollama）は「…モデル読み込み中」と表示する。
- ウィンドウは既定で最前面に固定（「設定」の「最前面に固定」で切り替え）。
- 「帯にする」で、字幕だけの軽量表示（テロップ）になる。タイトルバーのない帯で、背景は既定で不透明（「設定」の「帯」→「背景の透過率」で 0〜100% に変えられる）。**帯にする直前のウィンドウと同じ中心に、同じ横幅で**出る（動画の幅に合わせたいときは、先に通常ウィンドウの幅を合わせておく）。前回の位置は使わない（見失うため）。帯の縁には細い枠が常に出ていて、出てから約 10 秒は、その枠が黄色く点滅して見つけやすい。ドラッグで好きな位置へ動かし、縁の内側（幅 8pt。乗せるとカーソルが変わる）をドラッグしてサイズを変えられる（高さだけ次回も覚えている）。字幕の文字は、帯の大きさでは変わらず、通常画面の字幕と同じ大きさで出る（「設定」の文字サイズで両方が変わる）。帯を高くすると、最新の字幕の上に、それより前の字幕が薄く積み重なる。帯は、発話が無い間も消えずに表示し続け、全画面表示の動画の上にも重なる。**ESC**（または帯に出る「元に戻す」ボタン）で、元のサイズと位置の通常画面に戻る。ESC は帯にフォーカスがあるときだけ効く（帯をクリックするとフォーカスされる）。

## エージェントに任せて構築する

Codex や Claude Code などのコーディングエージェントに、構築とインストールを任せられる。リポジトリを開いて、「`AGENTS.md` の手順で Live Subtitle をインストールして」と頼めばよい。エージェントは、前提の確認、whisper のモデルのダウンロード（先に許可を求める）、署名 ID の選択、ビルドと入れ替え、起動の確認までを行う。**画面収録の許可、サインイン、フォルダへのアクセスの確認は、あなたが行う**（エージェントは、システム設定も認証情報も扱わない）。実行中のアプリを止めるときは、先に知らせる決まりになっている。

## 事前に用意するもの

**ビルドに必要なもの**

- Apple Silicon の Mac（macOS 13 以降）
- Xcode（または Command Line Tools）。Swift が要る（ScreenCaptureKit の橋渡し部分のビルドに使う）
- Rust と cmake（`brew install cmake`。whisper.cpp と、内蔵エンジンの llama.cpp のビルドに使う）

**音声認識（必須）: whisper のモデル 1 個（約 574 MB）**

```bash
mkdir -p ~/"Library/Application Support/LiveSubtitle"
curl -L -o ~/"Library/Application Support/LiveSubtitle/ggml-large-v3-turbo-q5_0.bin" \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo-q5_0.bin
```

別の場所に置くときは、`LIVE_SUBTITLE_MODEL` でパスを指定する。

**翻訳先（1 つ以上。「翻訳しない」で使うなら不要）**

- **内蔵（既定。無料でオフライン。ほかに何も入れなくてよい）**: アプリに入っている llama.cpp で訳す。要るのはモデル 1 個（約 14.4 GB）だけで、画面の「ダウンロード」ボタンで取得できる。下の「内蔵エンジン」を参照。
- **Ollama（無料でオフライン）**: Ollama を入れて起動しておき、モデルを取得する。
  ```bash
  ollama pull gemma4:26b-mlx
  ```
  モデル名は、お使いの Ollama で取得できるものを選ぶ（画面のメニューに、入っているモデルが並ぶ）。大きなモデルは、メモリを大量に使う（下の「おすすめの翻訳モデル」と「Ollama のメモリ解放」を参照）。
- **Claude**: Claude Code の `claude` コマンド（`~/.local/bin` など。別の場所は `LIVE_SUBTITLE_CLAUDE`）。サインインが要る（画面のボタンから始められる）。
- **Codex**: Codex の **App Server**。アプリが `codex app-server` として起動する（Codex CLI と同じ `codex` 実行ファイルを使う。別の場所は `LIVE_SUBTITLE_CODEX`）。`codex exec` や対話式の CLI は使わない。ChatGPT アカウントでのサインインが要る（画面のボタンから始められる）。

Claude と Codex は、サインインしていなければ、画面の「サインイン」ボタンから公式のブラウザ認証（OAuth）を始められる。アプリは認証情報を扱わず、状態の確認と、公式の手順の開始だけを行う（Claude は `claude auth`、Codex は App Server の `account/*`）。

**署名 ID（推奨）**: ビルドし直しても画面収録の許可が外れないように、固定の署名 ID を用意する（下の「ビルドと起動」を参照）。

## おすすめの翻訳モデル

初めて起動したときの翻訳先は、内蔵エンジン（Gemma 4 26B の QAT 版）。以前の版で翻訳先を選んでいた場合は、その設定がそのまま残る。

**Ollama の `gemma4:26b-mlx`** が、使用感として快適（作者の感想）。測った値は次のとおり。

| 項目 | 値 |
|---|---|
| 1 文あたりの翻訳 | 約 0.65〜2 秒（2 回目以降。初回の読み込みだけ約 13 秒） |
| ディスク | 約 18 GB |
| メモリ（載っているとき） | 約 25.7 GB |

内蔵エンジン（Gemma 4 26B の QAT 版）は、同じ 40 文で比べて、訳の質にはっきりした差は見つからず、1 文あたり約 0.15 秒速かった（下の「内蔵エンジン」を参照）。Ollama を入れていないなら、内蔵エンジンで足りる。

ほかに、`gpt-oss:20b`（ディスク 13 GB、メモリ約 13.7 GB）と `qwen3.8:27b-mlx`（ディスク 18 GB、メモリ約 20.0 GB）も、画面のメニューから選べることを確認した（速度は未計測）。複数のモデルを同時にメモリへ載せると、50 GB を超えることがある。

## 動作確認した環境

macOS 27.0.1／Apple M1 Max（メモリ 64 GB）／Ollama 0.35.0／Claude Code 2.1.286／Codex App Server 0.159.0／Rust 1.95.0／cmake 4.4.3／Swift 6.4

内蔵エンジンは、macOS 27.2.1／cmake 4.5.0／llama.cpp b12503 で確かめた。

## ビルドと起動

```bash
CODESIGN_IDENTITY="<署名 ID>" scripts/bundle.sh   # 既定の出力先: ~/Applications/Live Subtitle.app
```

ビルドは一時ディレクトリで行う（iCloud 同期下だと codesign が失敗するため）。
内蔵エンジンの `llama-server` は、初回だけ llama.cpp のソース（版を固定してある）を GitHub から取得してビルドする（数分かかる）。できたものは `~/Library/Caches/LiveSubtitle/` に置いて、次回から使い回す。
`CODESIGN_IDENTITY` を省くと ad-hoc 署名になり、**ビルドし直すたびに画面収録の許可が外れる**。固定の署名 ID を使うこと。

許可まわりは、次の「macOS の許可」を参照。

## macOS の許可

| 許可 | 必要か | いつ | 内容 |
|---|---|---|---|
| **画面収録とシステムオーディオ録音** | **必須** | 初めて「開始」を押したとき | システム音声を取るために要る。画面の映像は使わない（音声だけを取得する） |
| フォルダへのアクセス（デスクトップ、または選んだフォルダ） | 会話履歴を保存するときだけ | 初めて保存したとき | macOS が確認を出したら許可する |
| マイク | 不要 | — | マイクは使わない（Mac が出している音を取る） |
| アクセシビリティ／入力監視 | 不要 | — | Esc は、帯にフォーカスがあるときだけ読む。キー入力の常時監視はしない |

フォルダへのアクセスなど、上の表以外でも、macOS が許可を求めてきたら、内容を見て随時許可すればよい。

**画面収録とシステムオーディオ録音を許可する手順**

1. `Live Subtitle.app` を起動して「開始」を押す。許可がないと、赤い文字で「画面収録の許可が必要: …」と出る（macOS が確認のダイアログを出すこともある）。
2. システム設定 → プライバシーとセキュリティ → **画面収録とシステムオーディオ録音** を開き、`Live Subtitle` をオンにする。一覧になければ「＋」を押して、`~/Applications/Live Subtitle.app` を追加する（ファイル選択で `Cmd+Shift+G` を押し、パスを貼ると早い）。
3. もう一度「開始」を押す。まだ拒否されるときは、アプリを終了して起動し直す。

**つまずきやすい点**

- 許可は、アプリの**署名**に結びついている。ad-hoc 署名だと、ビルドし直すたびに許可が外れる。固定の署名 ID を使う（「ビルドと起動」を参照）。
- 署名を変えたあとは、一覧でオンのままでも拒否されることがある（古い署名の項目が残っているため）。その項目を「−」で削除してから、登録し直す。
- 許可を付けるアプリは、`/tmp` のような隠れた場所ではなく、`~/Applications` のように、ファイル選択で見つけやすい場所に置く。

## つまずいたときは（開発中に実際に踏んだこと）

| 症状 | 原因と対処 |
|---|---|
| 赤い「画面収録の許可が必要」が出る | 上の「画面収録とシステムオーディオ録音を許可する手順」を行う。オンなのに出るときは、項目を「−」で消して登録し直す |
| 音が出ているのにメーターが「無音」のまま／字幕が出ない | まず許可を確認する。次に、アプリ自身の音は取らない（除外している）ことと、音量が小さい音源でも自動音量補正で持ち上げることを知っておく |
| 字幕が遅れる | 翻訳先とモデルによる。内蔵は約 0.5〜1 秒、Ollama・Claude は約 1〜2 秒、Codex は約 2〜5 秒。Codex なら、Luna や Terra などの軽いモデルを選ぶ。翻訳が 10 秒以上待たされた行は、訳さず原文のまま出す |
| 開始した直後の最初の字幕が遅い | モデルの読み込み中（内蔵 約 7 秒、Ollama 約 13 秒、Claude 約 1.3 秒、Codex 約 5 秒）。「…モデル読み込み中」と出ている間は待つ |
| Mac のメモリが 50 GB 以上使われる | Ollama の大きなモデルが載っている。「設定」の「メモリ解放」を押す（起動時・終了時・モデル切り替え時にも自動で解放する）。強制終了で残った分は、次の起動時に片付く |
| 赤い「内蔵エンジンのモデル（…）がまだ無い」が出る | 横の「ダウンロード」ボタンを押す（約 14.4 GB）。別の GGUF を使うなら、「設定」の「GGUF ファイルを選ぶ…」 |
| 赤い「llama-server が起動できなかった」が出る | 続けて、サーバーが最初に出したエラーが表示される（全文は `~/Library/Application Support/LiveSubtitle/llama-server.log`）。選んだ GGUF が llama.cpp で読めない形式か、壊れているか、メモリが足りないことが多い。「設定」で推奨モデルに戻す |
| テストで Mac の音が急に大きくなった | このアプリは、Mac の出力音量にも、スピーカーへの信号にも触れない。自動音量補正は、取り込んだ複製にだけ掛かる。開発中に大きく聞こえたのは、フルレベルのテスト音（`say` や `afplay`）で、アプリの増幅ではなかった |
| 帯を見失った | 帯の縁には細い枠が常に出ている。帯にしてから約 10 秒は、その枠が黄色く点滅する。帯をクリックしてフォーカスし、Esc か「元に戻す」ボタンで通常画面に戻る。Esc は、帯にフォーカスがあるときだけ効く |
| Claude のサインインが完了しない | ブラウザ認証が自動で終わらない場合は、ターミナルで `claude auth login` を実行する（Claude のサインインの操作は、作者の環境では未確認） |
| アプリが予期せず終了した | `~/Library/Application Support/LiveSubtitle/crash.log`（パニックや終了の合図の記録）と、`~/Library/Logs/DiagnosticReports/` の `live-subtitle-*.ips`（macOS のクラッシュの記録）を見る。アプリを別の作業で止めたときにも、終了の記録は残る |
| `codesign` に失敗する | `~/Desktop` など iCloud 同期下で作ると失敗する。`scripts/bundle.sh` は一時ディレクトリでビルドするので、スクリプト経由で作る |

## 翻訳先ごとの仕組み（どう接続しているか）

アプリは、API キーを使わない。内蔵エンジンは、アプリに入っているサーバーを子プロセスとして起動する。Claude と Codex は、お使いの PC に入っている公式のコマンドを、アプリが子プロセスとして起動して使う（ログインは、そのコマンドが持っているものをそのまま使う）。

| 翻訳先 | 接続方法 |
|---|---|
| **Claude** | **`claude` コマンド（CLI）を起動**する。`claude -p` を標準入出力の stream-json 形式で起動したままにして、字幕 1 行を 1 メッセージとして流し込む。ふだんは 1 つだけで、発話が続いて翻訳が追いつかないときだけ、最大 3 つまで増やして並行して訳す（増えたプロセスは「停止」まで残る）。どのプロセスにも文脈が伝わるように、直前の 3 行をメッセージに添える。考える処理（thinking）・ツール・フック・設定の読み込み・セッション保存は、すべて切ってある。履歴が積み上がるので、プロセスごとに 40 行で新しいプロセスへ切り替える（次のプロセスは、裏で先に起動しておく）。 |
| **Codex** | **`codex app-server`（App Server）を起動**して、標準入出力の JSON-RPC で話す。サーバーは 1 つで、その上に使い捨て（ephemeral）のスレッドを 6 本立てて、字幕を並列に翻訳する（`thread/start` → 字幕ごとに `turn/start` → `item/agentMessage/delta` と `turn/completed` を受け取る）。承認は `never`、sandbox は `read-only`。モデルの一覧は `model/list`、サインインの確認と開始は `account/read`・`account/login/start`。 |
| **内蔵** | アプリに同梱した **llama.cpp の `llama-server` を起動**して、**HTTP の API** で話す。`127.0.0.1` の空いているポートで、モデルを 1 つ読み込み、同時に 1 行だけ訳す（`-ngl 999 -np 1 -c 4096 --reasoning-budget 0 --no-ui`）。翻訳は `POST /v1/chat/completions`（`temperature` 0、考える処理なし）、読み込みの完了は `/health` で待つ。 |
| **Ollama** | **HTTP の API** で話す（既定は `http://127.0.0.1:11434`。`OLLAMA_HOST` で変えられる）。翻訳は `POST /api/chat`（ストリームなし・考える処理なし・`keep_alive` 30 分）、モデル一覧は `/api/tags`、メモリ解放は `/api/ps` と `/api/generate`。 |

Codex は App Server 経由だけで使い、`codex exec` や対話式の CLI は使わない。内蔵エンジンのサーバーと、Claude と Codex のプロセスは、「停止」を押したときと、アプリの終了時に止める。

## 内蔵エンジン

Ollama などを入れなくても、アプリだけでローカルに訳せる。アプリに入っている llama.cpp のサーバー（`Live Subtitle.app/Contents/MacOS/llama-server`）が、GGUF 形式のモデルを動かす。

**モデル**

- 既定は、Google の **Gemma 4 26B（QAT 版、4 ビット）**。ファイルは `gemma-4-26B_q4_0-it.gguf`（約 14.4 GB、Apache 2.0、取得にサインインは要らない）。配布元は Hugging Face の [google/gemma-4-26B-A4B-it-qat-q4_0-gguf](https://huggingface.co/google/gemma-4-26B-A4B-it-qat-q4_0-gguf)。
- 手元にあれば、それを使う。サイズが合うものだけを使う。探す場所は、次の順。
  - このアプリのフォルダ（`~/Library/Application Support/LiveSubtitle/`）
  - Hugging Face のキャッシュ（`~/.cache/huggingface/hub`。`HF_HUB_CACHE`・`HF_HOME` があればそちら）。今の llama.cpp も、ここに取得する
  - Ollama の置き場（`~/.ollama/models`。`OLLAMA_MODELS` があればそちら）。Ollama で Hugging Face から取得したもの
  - LM Studio のフォルダ（`~/.lmstudio/models`、以前の版の `~/.cache/lm-studio/models`）と、llama.cpp の以前のキャッシュ（`~/Library/Caches/llama.cpp`。`LLAMA_CACHE` があればそちら）
- Hugging Face のキャッシュと Ollama は、ファイルの中身のハッシュ（SHA-256）をファイル名にしているので、名前で同じファイルだと分かる。LM Studio などは、ファイル名で探す。LM Studio で保存先を変えている場合は、見つけられない（下の「GGUF ファイルを選ぶ…」を使う）。
- 無ければ、画面に「ダウンロード（14.4 GB）」ボタンが出る。押すと `~/Library/Application Support/LiveSubtitle/` に取得する。途中で止めても、もう一度押せば続きから再開する。終わったらサイズとチェックサム（SHA-256）を確かめ、合わないものは使わない。
- 別のモデルを使うときは、「設定」のメニューから選ぶ。推奨モデルのほかに、上の場所で見つかった GGUF（1 GB 以上）が、持ち主のツールでの名前で並ぶ（例: `Ollama: hf.co/…:Q6_K`）。「探し直す」で調べ直す。メニューに出ない場所の GGUF は、「GGUF ファイルを選ぶ…」で指定する。
- メニューのほかのモデルは、動くかどうかも、訳の質も確かめていない。読み込めなければ、赤い文字で理由が出る。
  - Ollama が Hugging Face から取得した GGUF（`hf.co/…`）は、1 つ試して、読み込めて訳せた。
  - Ollama 自身が配っているモデルには、読み込めないものがある（`gpt-oss:20b` は「unknown model architecture: 'gptoss'」で失敗した。Ollama 独自の形式のため）。
  - Ollama の MLX 版（`gemma4:26b-mlx` など）は GGUF ではないので、メニューに出ない。

**メモリ**

- モデルは、「開始」を押したとき（動作中に内蔵へ切り替えたとき、ダウンロードが終わったときも）に読み込み、「停止」、アプリの終了、ほかの翻訳先やモデルへの切り替えで手放す（サーバーごと止める）。止めたあとは、次の「開始」まで読み込まない。「設定」の「メモリ解放」は、いったん手放すだけで、次に訳す行が来たら読み込み直す。
- 読み込んでいる間、実メモリに約 14 GB 載る（`ps` の RSS で 14.0 GB）。ほとんどがモデルのファイルをそのまま写した分で、プロセスが自分で確保したメモリ（`footprint` の値）は約 0.5 GB だった。
- アプリが強制終了されて、サーバーだけが残った場合は、次の起動時に止める（`llama-server.pid` に記録した、親のいなくなったサーバーだけ）。

**確かめた結果**

- 話し言葉風の英語 40 文を、アプリと同じ指示文・同じ文脈の付け方で、Ollama の `gemma4:26b-mlx` と交互に訳した。1 文あたりの中央値は、内蔵 0.75 秒（0.48〜0.90）、Ollama 0.88 秒（0.54〜1.26）で、40 文中 35 文で内蔵が速かった（差の中央値は 0.15 秒）。
- 訳の質は、同じ 40 文で、次の順に比べた（採点は 1 人、文は自作）。内蔵（QAT 版）と Ollama を、直接、伏せて読み比べてはいない。
  - Ollama の `gemma4:26b-mlx` と、QAT ではない 4 ビット版（`ggml-org/gemma-4-26B-A4B-it-GGUF` の Q4_0）を、どちらの訳か伏せて読み比べた。片方だけ劣る文は Ollama 4、Q4_0 版 6。はっきりした誤訳は、Q4_0 版の 1 文だった。
  - QAT 版と Q4_0 版は、40 文中 30 文が一字一句同じだった。違った 10 文のうち、意味に関わるのは上の誤訳の 1 文で、QAT 版では文の骨格が正しくなった（「うんざりしている」は落ちたまま）。
  - どのモデルも、`dry run` を「テスト走行」と訳した。
  - 文末の「。」「？」は、どのモデルも 40 文すべてで守った。
- 実物のサーバーとモデルでの自動テスト: 起動、翻訳、同じモデルでの使い回し、停止でプロセスが消えること、取り残されたサーバーを起動時に止めること。配布元からの途中再開（最後の 1 KB だけ取得して、チェックサムが合うこと）。
- モデルの探索: 仮の置き場での単体テスト（Ollama・Hugging Face・LM Studio のどこにあっても推奨モデルを見つけること、ほかのモデルの一覧と名前）。この Mac の実物では、Ollama の GGUF 2 個と、このアプリのフォルダの 1 個が並び、MLX 版は並ばなかった。
- 画面の操作（翻訳先の切り替え、ダウンロードのボタンと進み具合、モデルのメニューと GGUF の選択、メモリ解放）と、実際の音声での字幕は、自動の確認をしていない。

## Ollama のメモリ解放

大きなモデルは、メモリを数十 GB 使う。[Taceta](https://github.com/mlabo-org/taceta)（ローカル推論用の macOS クライアント）の「全モデル解放」と同じ方法（`/api/ps` で載っているモデルを調べ、各モデルに `keep_alive: 0` を送り、メモリから消えるまで待つ）で、次のときに解放する。**他のアプリが読み込んだモデルも対象**になる（次に使われたとき、再読み込みされる）。

- 「設定」の「メモリ解放」ボタンを押したとき
- アプリの起動時（異常終了の取りこぼしを片付ける）
- アプリの終了時
- Ollama のモデルを切り替えたとき、または翻訳先を Ollama から別のものに変えたとき（新しいモデルは、解放が終わってから読み込む）
- アプリがパニックしたとき、または SIGTERM／SIGINT／SIGHUP で終了させられたとき

Ollama が起動していなければ、起動はしない（載っているモデルはないものとして扱う）。強制終了などで、解放する機会がなかった場合は、次の起動時に片付く。それまでも、翻訳のリクエストに付けた `keep_alive`（30 分）を過ぎれば、Ollama が自分で解放する。

**実機で確かめた結果**

- 起動時: 起動の前に載っていた `gemma4:26b-mlx`（25.7 GB）と `qwen3.8:27b-mlx`（20.0 GB）が、起動直後に両方解放された（画面に「起動時: Ollama のモデルを 2 個、メモリから解放した」と出る）。
- 終了時: `gpt-oss:20b`（13.7 GB）を載せてからアプリを終了すると、解放された。
- 終了の合図（SIGTERM）: 同じく解放されてから、アプリが終了した。
- 疑似の Ollama サーバーを使った単体テスト: 複数モデルの解放、何も載っていない場合、解放できないモデルの理由の表示、Ollama が動いていない場合。
- 「メモリ解放」ボタンの押下と、モデル切り替え時の解放は、画面の操作が必要なので、自動の確認はしていない。

**対象外**

- 内蔵エンジンのサーバーと、Claude と Codex の子プロセスは、この機能の対象ではない。「停止」とアプリ終了のときに、別に止める。
- Ollama 以外（whisper のモデルなど）のメモリは、解放しない。

- `assets/vad/` 音声検出のモデル（アプリに埋め込む）
- `src/translate.rs` 翻訳先の切り替えと Ollama
- `src/builtin.rs` 内蔵エンジン（同梱した llama.cpp のサーバーの起動と停止、各ツールの置き場からのモデルの探索、ダウンロード）
- `src/claude.rs` 常駐した Claude CLI での翻訳
- `src/codex.rs` 常駐した Codex App Server での翻訳
- `src/main.rs` GUI
- `src/app_shell_foundation.rs` 表示設定の共通部品（app-shell-foundation が管理。編集しない）
- `examples/capture-spike.rs` 音声取得だけの動作確認
- `scripts/bundle.sh` ビルドと `.app` の作成・署名・入れ替え

- `AGENTS.md` コーディングエージェント向けの、インストール手順と開発の決まり

## 既知の制約

- このMacでは、取得した音声の音量がかなり小さい（RMS 約 0.005）。原因は未特定。自動音量補正（AGC。目標は約 -20 dBFS、最大 +36 dB、無音の間はゲインを固定）で持ち上げて whisper に渡す。区切り検出は、音量ではなく音声検出モデル（Silero VAD）で、同じ補正後の音から声の区間を判定する。風や人混みのような大きな環境音は、声として扱わない。
- 声のない区間は whisper へ渡さないが、音声検出は音楽を声と取り違えることがある（歌でなくても起きる）。そのときの幻聴（存在しない発話の出力）は、無音確率と記号だけの結果の除外で抑えているが、完全ではない。
